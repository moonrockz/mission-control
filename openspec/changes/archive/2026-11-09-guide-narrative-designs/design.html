Context

The bundle owns authoring instructions and templates as literals in apps/openspec-ext/bundle.mbt. The source installer generates seven managed files and an ownership lock. Consumers pin a released tools binary. See the proposal for the reader's problem.

Goals and non-goals

Help authors explain a concrete journey, a decision's reason and the alternatives considered. Preserve the required artifact structure and normative contracts. Do not add mandatory personas, diagram counts or a new prose validator.

Decisions

STORY-1. Connect decisions through a worked journey

A developer installs Morphir without .NET and then adds an F# frontend. At that point, the reader needs to understand why an AOT host uses a separate managed process. Carry that example into the readiness check: if the frontend fails, setup must keep the previous toolchain. The journey connects the runtime boundary and activation decision to their reasons.

Guide authors to introduce constraints at the relevant decision, explain the choice and alternatives, and include significant failures and recovery. Mark proposed commands and assumptions clearly. A list of isolated decisions loses this connection; a long fictional story can hide technical facts. One paragraph and one example suffice for small work.

BUNDLE-1. Ship portable guidance through the source bundle

Put the guidance in the schema instructions and matching templates, then install the bundle from source. Update the guide and publish the next tools patch release. A local edit in a consumer would fail its checksum check and would not help other projects. Durable spec examples belong under Purpose so they survive archive; requirements and scenarios retain their existing form.

bundle.mbt -> source installer -> managed snapshot and lock
           -> tools-v0.1.2 -> consumer install -> author instructions

Risks and trade-offs

Overlong stories can obscure decisions. The guidance explicitly scales detail to the change and avoids forced personas and diagram quotas. This release changes documentation content, so existing install, drift and compatibility checks verify delivery. It does not attempt to test the quality of arbitrary generated prose.

Migration

Set only the tools version to 0.1.2, regenerate the source snapshot and run existing checks. Land a reviewed release candidate and verify its published assets. Consumers update their pin and run the released installer. Existing designs are preserved. Reverting the consumer adoption restores the previous bundle and lock.
